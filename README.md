## Why Plain Text Is Awkward to Share

Plain text is the most honest format in computing: nothing but characters. That simplicity is its strength and its weakness.

When you share a .txt file, you're handing the reader a file with no agreed presentation. There's no font, no page size, no margins, no structure — just characters that will be rendered however the receiver's text editor decides. One person sees a tiny font; another sees one that fills the screen. Nobody sees the same thing.

Printing is worse. Text editors aren't print tools. Lines wrap wherever they feel like it, long lines get cut off, and there's no pagination worth the name. You've seen the result: a printout with a line chopped mid-word at the edge of the page.

And then there's the impression problem. A plain text file reads as unfinished — a draft, a scrap, something not ready to be shared. A PDF reads as a document. When the content matters, presentation matters, and PDF is the presentation that says "this is done."

There's also the long-term problem. Text files have been around since the beginning of computing, and they'll outlive most formats — but their presentation was never standardized. Open the same .txt file on Windows, macOS, a phone, and a web app, and you'll get four different-looking results. A PDF locks in one presentation, so the document you send is the document everyone sees. Same text, one look, everywhere.

## The Formatting Question, Answered Honestly

Let's be clear about what this tool is and isn't. It's a text-to-document converter, not a word processor. It won't add headings, bold, or tables — it takes the text you have and presents it properly. And that's exactly the right tool for most text files.

The font size control matters more than it sounds. Meeting notes in a 9-point font are a chore; the same notes at a readable size are a reference document. Code in a small font loses its line structure on the page; code at the right size prints cleanly. The tool lets you match the size to the content.

Page size is the practical choice: A4 for most of the world, Letter for US-standard contexts. If the PDF is going to a printer or a portal with expectations, matching the standard saves a round of scaling trouble.

And margins are the finishing touch. Tight margins cram the page; generous ones make it look airy and intentional. The right setting depends on the document — a dense log can justify tighter margins, while a draft meant to be annotated benefits from room.

One thing worth knowing: the tool preserves line breaks from your text file. For notes, that's exactly what you want — each line stays where it was. For code, it means the structure you worked hard on doesn't get reflowed into a mush.

There's also a practical angle for long files. A text file that scrolls for fifty screens becomes, in PDF form, a document with pages you can number, reference, and navigate. That matters for anything you'll print, circulate, or file — "see page four" works with a PDF in a way it never does with a text file.
